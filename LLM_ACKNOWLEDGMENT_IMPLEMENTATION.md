# LLM-Based Acknowledgment Implementation

## Overview

Implemented pure LLM-based acknowledgment responses for the real estate agent. After each user answer, the system now generates a dynamic, contextual acknowledgment before asking the next question.

**Approach Selected:** Option 2 (Pure LLM)
- Dynamic responses generated by ChatGPT for every answer
- No hardcoded templates
- Contextual and personalized

---

## Changes Made

### 1. State Updates (`broker_agent/state.py`)

Added three new fields to `RealEstateAgentState`:

```python
# LLM Acknowledgment
pending_answer: Optional[Any]           # The answer waiting to be acknowledged
pending_question_id: Optional[str]      # Which question the answer is for
last_response_text: Optional[str]       # LLM-generated acknowledgment text
```

Updated `create_real_estate_state()` to initialize these fields to `None`.

**Purpose:** Track which answer needs acknowledgment and store the generated response.

### 2. Acknowledgment Node (`broker_agent/nodes/acknowledge.py`) - NEW FILE

Created new node for LLM-based response generation:

```python
async def generate_acknowledgment(state: RealEstateAgentState) -> RealEstateAgentState
```

**Features:**
- Uses ChatOpenAI (gpt-4o-mini) with temperature=0.7
- Builds context-aware prompts based on question type and user answer
- Generates warm, encouraging, 1-2 sentence acknowledgments
- Fallback to generic message if LLM fails
- Clears pending fields after generating response

**Supports acknowledging:**
- `req_type` - Transaction type (Buy/Sell)
- `proximity_location` - Proximity-based location
- `budget` - Price range in crores
- `property_area` - Property size in sq ft
- `property_type` - Property type
- `special_requests` - Special features/requests

**Example Output:**
```
User answers: "buy"
LLM acknowledges: "Great! Buying a property is an exciting journey.
Let me help you find the perfect home that matches your needs."
```

### 3. Graph Routing Updates (`broker_agent/graph.py`)

Updated LangGraph workflow to include acknowledgment node:

**Old Flow:**
```
Question Node → END
```

**New Flow:**
```
Question Node → Acknowledge Node → END
```

**Changes:**
- Imported `generate_acknowledgment` from nodes
- Added acknowledge node to workflow: `workflow.add_node("acknowledge", generate_acknowledgment)`
- Routed all question nodes to acknowledge before END:
  ```python
  workflow.add_edge("ask_transaction_type", "acknowledge")
  workflow.add_edge("ask_location", "acknowledge")
  workflow.add_edge("ask_price_range", "acknowledge")
  workflow.add_edge("ask_property_area", "acknowledge")
  workflow.add_edge("ask_property_type", "acknowledge")
  workflow.add_edge("ask_special_features", "acknowledge")
  ```

### 4. Service Layer Updates (`broker_agent/service.py`)

Enhanced `process_user_input()` method:

**Before:**
1. Update state with user input
2. Invoke graph to get next question
3. Return state

**After:**
1. Update state with user input
2. **Set pending_answer and pending_question_id** ← NEW
3. Invoke graph to get next question
4. Acknowledge node generates response using pending fields
5. Return state with acknowledgment in `last_response_text`

**Code:**
```python
# Set pending answer for LLM acknowledgment
state = {
    **state,
    "pending_answer": user_input,
    "pending_question_id": current_question_id,
}
```

## Conversation Flow

### Request 1: Create Session
```
POST /sessions
↓
Router → No pending data, ask Q1
↓
Acknowledge → No pending answer, skip
↓
Return Q1 (Transaction Type)
```

### Request 2: Submit Answer to Q1
```
POST /sessions/{id}/answer
{"answer": "buy", "question_id": "req_type"}
↓
Service updates: req_type="buy"
Service sets: pending_answer="buy", pending_question_id="req_type"
↓
Graph routes: req_type is set → ask Q2
↓
Acknowledge generates: "Great! Buying a property is exciting..."
↓
Return Q2 + acknowledgment for Q1
```

### Request 3: Submit Answer to Q2
```
POST /sessions/{id}/answer
{"answer": "my_work", "question_id": "proximity_location"}
↓
Service updates: proximity_location="my_work"
Service sets: pending_answer="my_work", pending_question_id="proximity_location"
↓
Graph routes: proximity_location is set → ask Q3
↓
Acknowledge generates: "Working near home saves commute time..."
↓
Return Q3 + acknowledgment for Q2
```

## LLM Prompt Template

The acknowledge node uses a template from `prompts/acknowledgment.txt` that builds natural, conversational responses. The prompt includes:

**Key Features:**
- Loads conversation history with all previous answers
- Knows what question to transition toward
- Instructs LLM to sound natural and human
- Avoids corporate jargon and generic responses
- Validates the choice and moves conversation forward

**Example Generated Responses:**
```
User budget Q3: "₹1.2Cr - ₹2.1Cr"
LLM: "That budget gives you great options - you'll find some really nice properties in that range."

User property area Q4: "2,200 - 5,000 sq ft"
LLM: "Good size range, that opens up a lot of possibilities for what you're looking for."

User property type Q5: "Apartment"
LLM: "Apartments are great if you want community amenities and hassle-free maintenance."
```

The prompt is stored in `prompts/acknowledgment.txt` with placeholders for dynamic values:
- `{conversation_so_far}` - Previous answers
- `{formatted_answer}` - Current answer
- `{next_hint}` - Context about what comes next

## Error Handling

If LLM fails:
- Logs error
- Falls back to generic message: "Got it! Let me find the perfect match for you."
- Sets error field in state
- Conversation continues normally
